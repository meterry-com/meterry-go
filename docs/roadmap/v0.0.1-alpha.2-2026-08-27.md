# v0.0.1-alpha.1 Roadmap

Date: 2026-08-27

## Release Goals

- Move project-scoped realtime usage-control reads to `subject/realtime/limits`.
- Keep the legacy wallet-limits snapshot entry point so existing callers can migrate smoothly.
- Fill in type definitions and tests so the public JSON shape only exposes stable fields.

## Change Log

- Added `ManagerClient.ReadSubjectRealtimeLimitsForProject` for `/v1/projects/:project_id/subject/realtime/limits`.
- Added `types.SubjectRealtimeLimitsSnapshot` and `types.SubjectRealtimeLimitItem`.
- `ReadVirtualWalletLimitsForProject` now sources from the subject realtime limits API while preserving the legacy snapshot shape.
- Added `ReadRealtimeWalletLimitsForProject` as a compatibility alias to support gradual migration.
- `ReadVirtualWalletAmountForProject` remains unchanged as the realtime balance helper.
- README now documents the new helpers and deprecation guidance.
- Tests now cover the new endpoint, compatibility mapping, and public-field redaction.

## Compatibility Notes

- The legacy wallet-limits path still works, but callers should migrate to `ReadSubjectRealtimeLimitsForProject`.
- `ReadVirtualWalletLimitsForProject` and `ReadRealtimeWalletLimitsForProject` currently return the same compatibility structure.
- Subject realtime limits no longer repeat wallet amount fields.

## Next Steps

- Continue migrating callers to `ReadSubjectRealtimeLimitsForProject`.
- Revisit the legacy wallet-limits wrapper in a later release if and when the migration is complete.
