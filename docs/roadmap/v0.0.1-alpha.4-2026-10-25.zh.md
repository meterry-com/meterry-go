# SDK 未发布路线图

更新日期：2026-10-25。以下变更已在开发分支实现，尚未打发布标签。

## 自定义限额上限更新

- 新增 `ManagerClient.UpdateRuleAccountLimit(ctx, id, req)`，调用 `PATCH /v1/projects/:project_id/usage-control-rules/limits/:id`，项目作用域使用客户端配置。
- 新增 `types.UpdateRuleAccountLimitRequest`，仅包含 `LimitAmount`，以十进制字符串 `limit_amount` 提交。不提供用量、周期、模式、选择器或身份修改字段。
- 直接返回 `*types.SubjectRealtimeLimitItem`，保留维度范围、当前用量、剩余额度、超限状态和下次重置时间。该公开快照新增 `PeriodType`（`period_type`），避免解码时丢失服务端周期模式。
- 需要 `usage_control:write` 权限及支持此接口的服务端。仅允许修改 active 的独立自定义规则；Plan 自身的规则和已停用规则不允许修改。主体绑定 Plan 后，其独立自定义规则仍可更新。
- 成功后立即使用新上限，保留当前用量与周期。允许上限低于当前用量，返回的 `Exceeded` 与 `RemainingAmount` 反映新上限。
- HTTP 错误继续使用现有 `APIError`。SDK 不执行重置、不伪造用量事件，也不在服务端响应前修改本地快照。

## 验证范围

- PATCH 方法、项目路径、Bearer 鉴权及只含上限的十进制 JSON 请求体。
- 直接解码实时响应，保留十进制精度、维度范围、周期模式和重置时间。
- 校验失败、权限不足、规则不存在及实时缓存错误的透传。
- 公开 JSON 不暴露内部缓存键、定点比例和用量版本。
