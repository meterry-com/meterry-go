# v0.0.1-alpha.3 路线图

日期：2026-09-30（标签提交日期）

变更范围：`v0.0.1-alpha.2` → `v0.0.1-alpha.3`，截至提交 `ba2a080`。

## 本次版本目标

- 将项目作用域统一配置在客户端，简化管理、查询和事件摄取接口。
- 补齐按 subject 查询用量控制规则与获取具体限额 ID 的能力。
- 提供签发短期 subject JWT 的 SDK 入口。

## 变更记录

### 客户端统一绑定项目

- `Config` 新增必填字段 `ProjectID`，`APIKey` 从可选改为必填；初始化时去除首尾空白并拒绝空值。
- `Manager`、`Query` 和 `Ingest` 的项目级操作统一使用客户端配置的项目 ID。
- 原有带 `ForProject` 后缀的方法移除该后缀及 `projectID` 参数，覆盖账户、subject 绑定、钱包、代金券、用量控制规则、预算租约、用量与账单查询等接口。
- 规则集管理、`Query.Report`、事件列表和详情查询、单条及批量 ingest 接口也移除 `projectID` 参数；`ChartQuery` 移除 `ProjectID` 字段。
- 租户身份由 API key 鉴权，无需配置 tenant ID，也不发送 `X-Tenant-ID` 请求头。

### 用量控制规则与限额 ID

- 新增 `ManagerClient.ListUsageControlRulesBySubject(ctx, subjectType, subjectID)`，由服务端按 subject 筛选规则，并自动分页汇总结果；原有按账户查询入口迁移为 `ListUsageControlRules`。
- `types.ListUsageControlRulesRequest` 新增 `SubjectType`、`SubjectID`，`AccountID` 的 JSON 字段改为可选。
- `types.SubjectRealtimeLimitItem` 和 `types.VirtualWalletLimitSnapshot` 新增可选 `ID` 字段（JSON 为 `id`），兼容快照映射保留该字段，便于调用 `DeleteRuleAccountLimit` 删除具体限额。

### Subject JWT 签发

- 新增 `ManagerClient.GrantSubject`，调用 `POST /v1/subject/grants`。
- 新增 `types.GrantSubjectRequest`、`types.GrantSubjectResponse` 和权限常量 `types.TenantAPIKeyScopeSubjectJWTGrant`（`subject_jwt:grant`）。
- 请求支持 `SubjectType`、`SubjectID`、`Rules`、可选 `Metrics` 和 `ExpiresIn`；`Rules` 当前支持 `analysis`。省略 `Metrics` 表示允许所有指标，提供非空列表可限制指标范围；`ExpiresIn` 单位为秒，省略时使用服务端默认有效期。
- 返回 token 类型、访问 token、有效期、过期时间（Unix 秒）、subject、规则和可选指标列表。
- 必须使用绑定目标项目且具有 `subject_jwt:grant` 权限的租户 API key；固定服务 API key 不支持签发。服务端从 API key 推导租户和项目，不从客户端配置的 `ProjectID` 取得授权范围。

### 文档与测试

- README 补充项目绑定配置、破坏性变更迁移提示和 subject JWT 使用示例。
- 标签内新增或更新测试，覆盖初始化校验、配置项目与鉴权头、限额 ID 解码及兼容映射、公开 JSON 字段约束，以及 JWT 请求/响应和 400、401、403 错误透传。

## 兼容性说明与迁移

本次版本包含破坏性 API 变更，升级时需要同步调整调用代码。

1. 在 `sdk.Config` 中配置 `ProjectID`、`BaseURL` 和 `APIKey`；每个租户/项目组合使用独立客户端。
2. 将旧方法的 `ForProject` 后缀和项目 ID 实参移除，例如：

   ```go
   // alpha.2
   account, err := client.Manager.CreateAccountForProject(ctx, projectID, req)
   // alpha.3：projectID 已配置在 sdk.Config.ProjectID 中
   account, err := client.Manager.CreateAccount(ctx, req)
   ```

3. 对没有 `ForProject` 后缀的规则集、报告、事件列表和 ingest 方法，同样移除项目 ID 实参，并删除 `ChartQuery.ProjectID` 配置。
4. 原钱包限额兼容入口改名为 `ReadRealtimeWalletLimits` 和 `ReadVirtualWalletLimits`，仍保留旧快照结构且已弃用；建议使用 `ReadSubjectRealtimeLimits`。实时余额入口改名为 `ReadVirtualWalletAmount`。
5. 接入 `GrantSubject` 时，确认 API key 绑定的项目与客户端配置一致，并具备签发权限。

## 后续规划

以下为升级后的迁移建议：

- 完成调用方的项目配置和方法签名迁移。
- 逐步迁移至 `ReadSubjectRealtimeLimits`，后续再评估移除旧钱包限额兼容包装。
- 按需接入 subject 规则查询与 JWT 签发流程。
