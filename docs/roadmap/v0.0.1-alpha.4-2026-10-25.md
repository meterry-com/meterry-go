# Unreleased SDK Roadmap

Updated: 2026-10-25. These changes are implemented on the development branch and have not been tagged as a release.

## Custom limit ceiling updates

- Added `ManagerClient.UpdateRuleAccountLimit(ctx, id, req)` for `PATCH /v1/projects/:project_id/usage-control-rules/limits/:id`. Project scope comes from the client configuration.
- Added `types.UpdateRuleAccountLimitRequest`, containing only `LimitAmount` (`limit_amount` as a decimal string). No usage, window, mode, selector or identity mutation fields are exposed.
- Returns the updated rule directly as `*types.SubjectRealtimeLimitItem`, preserving dimension scope, current usage, remaining amount, exceeded state and next reset time. Added `PeriodType` (`period_type`) to that public snapshot type so the server's window mode survives decoding.
- Requires `usage_control:write` and a server with this endpoint. Only active custom subject-route limits are accepted; Plan-owned rules and disabled rules are rejected. Custom rules on a Plan-bound subject remain eligible.
- Successful updates take effect immediately without resetting current usage or the cycle. A ceiling below current usage is allowed; `Exceeded` and `RemainingAmount` reflect the new ceiling.
- HTTP errors retain the existing `APIError` contract. The SDK does not perform resets, synthesize usage events, or mutate the local snapshot before receiving the server response.

## Verification

- Request method, project-scoped URL, bearer authorization and ceiling-only decimal JSON body.
- Direct realtime response decoding, including decimal precision, dimension scope, period mode and reset time.
- Propagation of validation, permission, not-found and realtime-cache errors.
- Public serialization excludes internal cache keys, scales and usage versions.

## Compatibility and next steps

This is an additive SDK change. Existing methods retain their signatures. Deploy the matching billing endpoint before adopting the new method, then select a release tag through the normal release process.
